# PHP-сайт, MySQL и сервис RAG

## Обновление работающего сайта

В существующей папке проекта на ветке `main` выполните:

```powershell
git pull --ff-only origin main
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
ollama pull qwen3:8b-q8_0
```

Сохраните существующее окружение, `RAG_DATA_DIR`, BGE-M3 и настройки MySQL. Если PHP развёрнут отдельно, перенесите туда изменения из `agent/`, сохранив локальный `db.php`. Если раньше вы явно задавали `RAG_MODEL`, для Q8 задайте `$env:RAG_MODEL = "qwen3:8b-q8_0"` в окружении запуска сервиса. Можно оставить установленный Q4 через `RAG_MODEL=qwen3:8b`.

Реранкер скачивается из Hugging Face при первом поиске под учётной записью сервиса. Чтобы подготовить веса заранее и избежать задержки первого запроса, выполните под той же учётной записью:

```powershell
.\.venv\Scripts\python.exe -c "from huggingface_hub import snapshot_download; snapshot_download('Qwen/Qwen3-Reranker-4B', allow_patterns=['*.json','*.safetensors','*.model','*.txt','*.jinja'])"
```

Реранкер работает локально через PyTorch. На GPU веса 4B в FP16 занимают около 8 ГБ, на CPU в FP32 около 16 ГБ; дополнительно нужна память для вычислений и моделей Ollama. При нехватке видеопамяти задайте `$env:RAG_RERANK_DEVICE = "cpu"` (медленнее). Для работы без интернета можно указать в `RAG_RERANKER` локальный каталог модели.

В используемой сайтом базе MySQL проверьте колонку:

```sql
SHOW COLUMNS FROM queries LIKE 'files_json';
```

Только если результат пустой, выполните один раз:

```sql
ALTER TABLE queries ADD COLUMN files_json JSON NULL;
```

Перезапустите работающий процесс `service.py` с теми же переменными окружения. В Windows команда запуска из корня проекта — `.\.venv\Scripts\python.exe service.py`. Оригиналы, задания и история находятся в прежних хранилищах. Сервис при запуске добавляет точный поиск для уже проиндексированных карточек сайта вида `faq_ticket_<id>.txt`, если в каталоге оригиналов сохранился файл. Если задание завершилось ошибкой, откройте заявку и повторите публикацию.

Чтобы применить структурную нарезку к прежним загрузкам, повторно загрузите документы под прежними именами. Для документов из папки повторите синхронизацию (при использовании встроенного Qdrant запускайте CLI-индексатор в момент остановки сервиса). Старые ссылки остаются привязаны к своим редакциям. Для демонстрации уточнения в выдаче должны быть оба пункта учебного регламента из `examples/Агентские договоры.md`.

## Первоначальная настройка

Установка Python, OCR, моделей и переменные окружения описаны в [README.md](README.md). Сайт в папке `agent/` рассчитан на существующую базу с пользователями, вопросами и заявками. В `agent/db.php` задайте подключение PDO к MySQL и константы `RAG_API_TOKEN`, `RAG_REVIEW_TOKEN`. У процесса Python должны быть такие же значения переменных окружения. Ключи различаются. Нужны расширения PHP PDO MySQL, mbstring и cURL. PHP обращается к Python на сервере по адресу `127.0.0.1:8765`. Путь к постоянным данным задаётся в `RAG_DATA_DIR`. Если нужна кнопка «На почту», укажите адрес службы качества в переменной окружения PHP `QUALITY_EMAIL`.

Для исходной таблицы вопросов, в которой ещё нет полей интеграции, примените отсутствующие части миграции:

~~~sql
ALTER TABLE queries
    ADD COLUMN chat_id VARCHAR(64) NOT NULL DEFAULT 'default',
    ADD COLUMN request_id CHAR(32) NULL,
    ADD COLUMN rag_result JSON NULL,
    ADD COLUMN files_json JSON NULL,
    ADD COLUMN ticket_id BIGINT NULL,
    ADD COLUMN human_answer TEXT NULL,
    ADD COLUMN reviewer VARCHAR(120) NULL,
    ADD COLUMN review_revision INT NOT NULL DEFAULT 0,
    ADD UNIQUE KEY uq_queries_request (user_id, chat_id, request_id),
    ADD INDEX ix_queries_chat (user_id, chat_id, id);
~~~

## Ответы и вложения

Поиск объединяет ранги для полного вопроса и короткого запроса по его предмету. Реранкер
упорядочивает кандидатов. До выбора ответа агент проверяет, зависит ли применимость правила
от недостающего условия. С уточнением сохраняется исходный вопрос, чтобы следующая короткая
реплика дополнила его. Модель выбирает номера строк, а сервис возвращает текст этих строк после
отдельной проверки, что они подтверждают запрошенный факт. Для демонстрации
сценария с типом контрагента загрузите `examples/Агентские договоры.md` и дождитесь индексации.
Обновление логики поиска применяется после перезапуска Python с прежним индексом.

Оба обработчика вопросов вызывают `ask_site_question()`. Он отправляет в `POST /ask` пользователя из сессии, диалог, уникальный идентификатор запроса, вопрос и недавнюю историю MySQL. Python использует до пяти сообщений по умолчанию. Когда предыдущий ход — уточнение, сервис получает также его текст, чтобы распознать короткий выбор сотрудника.

В `queries.rag_result` хранится полный ответ с ранжированными фрагментами `hits` и позициями цитат `used` (с нуля). **PHP записывает `queries.files_json` в той же операции INSERT**. Это массив использованных документов с полями `version`, `name`, `location` и `rank`. Несколько цитат одной версии дают одну ссылку. Для ответа без цитат массив пуст. Для старых строк с NULL кабинет восстанавливает ссылки из сохранённых `hits` и `used`, когда эти поля есть.

Кабинет формирует ссылку `download.php?query_id=…&version=…`. Обработчик проверяет владельца вопроса и наличие версии среди цитат, затем запрашивает оригинал у Python. Версия — строка из 64 шестнадцатеричных символов. Токен сервиса остаётся на сервере.

## Заявки и публикация

Если источников недостаточно, сотрудник может нажать «Создать заявку админу». Сайт связывает запись в MySQL `tickets` с конкретным вопросом. При ответе администратора текст сохраняется в `tickets.admin_answer` и виден автору вопроса. При выборе «Ответить и добавить в базу знаний» сайт также отправляет карточку вопроса и ответа в очередь Python. Статус «Опубликовано» в админке соответствует завершённой индексации.

Точный повтор опубликованного вопроса возвращает утверждённый ответ и карточку до классификации темы моделью. Регистр и лишние пробелы не влияют на совпадение. Для переформулировок работает обычный поиск по Qdrant и проверка цитат. Это обновление базы знаний RAG, веса Qwen остаются прежними. Новая публикация по той же заявке заменяет её активную редакцию. Личный ответ сам по себе в индекс не добавляется.

## Проверка после обновления

### Удаление документа

В панели администратора найдите нужную строку в «Документы базы знаний» и подтвердите удаление.
Загрузки сайта обозначены префиксом `upload:`, решения Streamlit — `quality:`, документы
из синхронизируемой папки — относительным путём. Удаление распространяется на редакции выбранного
источника, скачивание по старым ссылкам, фрагменты Qdrant, ответы в кеше и сообщения,
при подготовке которых сервис использовал эти фрагменты или связанные реплики. Публикации по
связанным заявкам тоже отзываются. Сотрудник вместо прежней цитаты увидит «Источник ответа удалён».
Решение администратора, внесённое независимо по другой заявке, остаётся самостоятельным источником.

Сервис ждёт завершения текущих запросов и индексации, затем отзывает источник. Очистка
файлов и векторов при сбое повторяется фоновым заданием. При общем содержимом нескольких
документов физическая копия хранится, пока нужна хотя бы одному из них. Внешний файл в
`RAG_DOCS_DIR` остаётся у владельца, а синхронизация пропускает удалённый путь. Для новой
осознанной загрузки используйте другое имя. У сотрудника могут остаться ранее скачанные копии.

Оба компонента разворачивайте вместе, включая новые `withdrawal.py` и `agent/withdrawals.php`.
PHP очищает связанные строки MySQL по идентификаторам отозванных ответов. При прерывании
он повторяет операцию при следующем обращении к кабинету. Для показа истории нужен доступ к
сервису RAG. Дополнительная ручная миграция MySQL для удаления не требуется.

### Сценарии

1. Задайте «Кто подписывает агентский договор?» по учебному регламенту. После уточнения напишите «физическое». Проверьте ответ, пункт 2.1 и скачивание оригинала после обновления страницы.
2. Задайте вопрос, которого нет в документах. Проверьте, что заявка появляется в админке только после нажатия кнопки сотрудником.
3. Опубликуйте ответ на эту заявку, дождитесь статуса «Опубликовано» и задайте тот же вопрос из другого аккаунта. Сверьте текст ответа и скачанную карточку.
