# Ответы по корпоративным регламентам

Локальный консультант по корпоративным регламентам. Сотрудник задаёт вопрос, видит цитаты, ранжирование и может скачать оригинал каждой использованной редакции. Администратор отвечает на заявки лично или публикует решение в общей базе. Опубликованное решение появляется в поиске после индексации. Подключение кнопок PHP-сайта, хранение переписки в MySQL и запуск отдельного HTTP-сервиса описаны в [INTEGRATION.md](INTEGRATION.md).

Для обновления существующего сайта см. [инструкцию по обновлению, полю files_json и публикации ответов](INTEGRATION.md#обновление-работающего-сайта).

## Первый запуск из ZIP на Windows

При работе с копией из Git выполните шаги установки ниже из корневой папки репозитория. Для запуска PHP-сайта из папки `agent` скопируйте `agent/db.example.php` в `agent/db.php` и укажите свои параметры MySQL. Для запуска демо в Streamlit достаточно Python и Ollama.

1. Полностью распакуйте ZIP. Откройте папку, где лежат `main.py` и `requirements.txt`. В адресной строке Проводника введите `powershell` и нажмите Enter. Все команды ниже выполняйте в этом окне.
2. Установите Python для Windows x64 и включите опцию добавления Python в PATH. Проект проверен на Python 3.14.3. [Скачать Python](https://www.python.org/downloads/windows/)
3. Установите и запустите Ollama. Если ставили Python или Ollama при открытом PowerShell, заново откройте его в папке проекта. Интернет понадобится для первой загрузки зависимостей и моделей. Qdrant работает локально из Python-пакета. [Скачать Ollama](https://ollama.com/download)

Один раз установите зависимости и модели:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe setup_ocr.py
ollama pull qwen3:8b-q8_0
ollama pull bge-m3
```

Для первого запуска на учебном регламенте выполните:

```powershell
$env:RAG_DOCS_DIR = "examples"
$env:RAG_REVIEW_TOKEN = Read-Host "Задайте ключ для рабочего места службы качества"
.\.venv\Scripts\python.exe indexer.py
.\.venv\Scripts\python.exe -m streamlit run main.py --server.address 127.0.0.1
```

Откройте [интерфейс сотрудника](http://localhost:8501). Через переключатель в боковой панели доступно рабочее место специалиста. Введите заданный при запуске ключ. Общий ключ рассчитан на демонстрацию на одном компьютере. Все сотрудники приложения видят один набор документов.

**Повторный запуск.** Для остановки нажмите Ctrl+C в окне Streamlit. В той же консоли достаточно повторить последнюю команду. В новом окне PowerShell снова задайте `RAG_DOCS_DIR`, ключ специалиста и, если использовали отдельную базу, `RAG_DATA_DIR`. Индекс и заявки сохраняются на диске. Если индексатор сообщает об ошибке соединения с Ollama, запустите приложение Ollama и проверьте командой `ollama list`, что видны обе модели.

## Три сценария для показа

В папке `examples` лежит вымышленный регламент АД-01.

| Сценарий | Что ввести | Что проверить |
| --- | --- | --- |
| Ответ по регламенту | «Кто подписывает агентский договор с физическим лицом?» | Цитата о коммерческом директоре с указанием пункта 2.1. Под ответом можно раскрыть ранжирование. |
| Уточнение | «Кто подписывает агентский договор?» Затем «С юридическим лицом». | Агент спрашивает о типе контрагента. После уточнения показывает пункт 2.2 о генеральном директоре. |
| Пробел в регламенте | «Где хранится бумажный оригинал агентского договора?» | Сотрудник нажимает «Создать заявку админу» и видит номер заявки. Специалист открывает её и утверждает ответ «Бумажный оригинал агентского договора хранится в архиве договорного отдела». В чате можно проверить решение и задать вопрос другими словами. Источником будет решение службы качества. |

Сквозной тест запускается командой `.\.venv\Scripts\python.exe smoke_test.py`. Он создаёт временную базу, выполняет три сценария через настоящий Ollama и проверяет поиск утверждённого решения после повторного открытия Qdrant.

## Свои документы

1. Поместите действующие регламенты в папку `documents` либо задайте путь через `RAG_DOCS_DIR`. В одной папке можно смешивать Word, PDF, изображения, Markdown и UTF-8 TXT.
2. Для испытаний на корпоративных данных задайте отдельный `RAG_DATA_DIR`, например `$env:RAG_DATA_DIR = ".rag-company"`, до запуска индексатора и Streamlit. В папке данных хранятся Qdrant, очередь и утверждённые решения.
3. Запустите `.\.venv\Scripts\python.exe indexer.py`, затем Streamlit в той же консоли и откройте адрес из вывода. Для второго экземпляра рядом с демо укажите `--server.port 8502`. При работающем приложении изменения можно применить кнопкой **Синхронизировать папку** на рабочем месте специалиста. Встроенный Qdrant открывается одним процессом одновременно.

Например, для своих документов остановите демо сочетанием Ctrl+C, создайте рядом с `main.py` папку `documents`, положите туда файлы и выполните:

```powershell
$env:RAG_DOCS_DIR = "documents"
$env:RAG_DATA_DIR = ".rag-company"
$env:RAG_REVIEW_TOKEN = Read-Host "Ключ службы качества"
.\.venv\Scripts\python.exe indexer.py
.\.venv\Scripts\python.exe -m streamlit run main.py --server.address 127.0.0.1
```

Индексатор синхронизирует весь выбранный каталог, включая подпапки. Он переиспользует неизменённые файлы, заменяет изменённые версии и исключает удалённые документы после успешной индексации каталога. Пустая папка и полностью нечитаемый файл дают ошибку. Ответы службы качества хранятся отдельно и переживают синхронизацию. Действующие редакции определяет владелец папки. Для нескольких процессов задайте `QDRANT_URL` и используйте один и тот же каталог с SQLite на одном хосте.

### Word, PDF и сканы

| Формат | Что попадёт в поиск |
| --- | --- |
| Word DOCX | Текст, заголовки, таблицы и печатный текст на встроенных растровых сканах в основной части документа. |
| Word DOC (97–2003) | Текст из классического двоичного документа. Для сканов внутри старого DOC сохраните документ как PDF или DOCX. |
| PDF | Текстовый слой и распознанный текст сканированных страниц. Страницы одного файла могут быть разного типа. В источнике сохраняется номер страницы. |
| PNG, JPEG, TIFF, BMP, WebP | Распознанный текст изображения. У многостраничного TIFF каждый лист получает свой номер. |

OCR работает локально для русского и английского печатного текста. Скрипт `setup_ocr.py` один раз скачивает модели Tesseract. Для машины без доступа к интернету можно скопировать подготовленную папку `.ocr-models` в проект. Распознанные фрагменты получают отметку **OCR** в ссылке на источник. Суммы, номера и фамилии на слабых сканах стоит сверять с указанной страницей. Рукописи и восстановление структуры сложных таблиц не входят в проверенные сценарии.

Проверку форматов с настоящим OCR можно запустить командой `.\.venv\Scripts\python.exe -m unittest -v test_ingestion`. При первой синхронизации после обновления ранее добавленные PDF и DOCX будут прочитаны заново.

## Как устроен ответ

Самостоятельный вопрос уходит в поиск дословно. При коротком продолжении вроде «А с юридическим?» агент использует окно из пяти рабочих сообщений вместе с текущим вопросом. Посторонняя реплика остаётся видна в переписке и исключается из рабочего контекста. История демо хранится в SQLite. Сохраните адрес чата из браузера в закладках: в нём личный ключ для восстановления диалогов. **Новый диалог** создаёт пустой чат; к прежнему можно вернуться через боковую панель. Переписка из старой версии, которая жила только в памяти браузера, недоступна после её перезапуска.

В разделе **Администратор** выберите один или несколько файлов и нажмите **Добавить документы**. Во время OCR и индексации можно задавать вопросы по готовым регламентам. Результат обработки виден в очереди. Кнопка **Ответить сотруднику** доставляет личный ответ. **Ответить и добавить в базу знаний** также ставит публикацию в очередь с повтором при недоступном Ollama или Qdrant. Для проверки сохранения истории, разграничения ролей и фоновых работ выполните `python -m unittest -v test_consultant test_ingestion` из окружения проекта.

При дословном повторе самостоятельного вопроса в том же диалоге сервис возвращает уже проверенный ответ с прежними источниками. Смена действующей редакции, публикация нового решения, изменение модели или количества результатов поиска требуют новой проверки. Уточнения и заявки об отсутствии информации каждый раз обрабатываются с учётом текущего диалога.

- `documents.py` разделяет нумерованные пункты и строки таблиц Word, сохраняет заголовки и первую строку таблицы в контексте. Внутри длинного пункта фрагменты содержат до 1300 символов с повтором целых предложений до 200 символов, если они помещаются. Отдельное длинное предложение разбивается по словам.
- Qdrant подбирает до 20 кандидатов после объединения смыслового и лексического поиска. Qwen3-Reranker-4B оценивает каждую пару «вопрос — фрагмент», шесть лучших по умолчанию поступают на проверку. В интерфейсе видны обе оценки. Перед выбором ответа агент проверяет недостающие условия, затем выбирает номера строк источника и отдельно проверяет, содержится ли в этих строках ответ.
- `agent.py`, `ollama_api.py` используют Qwen3 8B для выбора действия и фрагмента. Для сходно сформулированных правил проверяется, указал ли сотрудник различающее условие. Отдельный запрос к модели проверяет применимость выбранной цитаты с учётом альтернатив. Текст ответа берётся непосредственно из фрагмента. Модель всё ещё может выбрать неподходящий пункт, особенно если нужная оговорка за пределами выдачи. После двух безрезультатных уточнений сотрудник может отправить вопрос администратору кнопкой.
- `main.py` содержит Streamlit-чат, просмотр ранжирования и рабочее место службы качества. Очередь хранится в SQLite. Сообщения из чата поступают в базу знаний только после утверждения специалистом. Обратная связь обновляет поисковый индекс. Веса Qwen остаются исходными.

## Настройки

В `config.py` заданы значения по умолчанию. Переменные окружения применяются при запуске.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Локальный сервер моделей |
| `RAG_MODEL` | `qwen3:8b-q8_0` | Выбор действия и проверка цитаты |
| `RAG_RERANKER` | `Qwen/Qwen3-Reranker-4B` | Репозиторий Hugging Face или путь к скачанной модели |
| `RAG_RERANK_DEVICE` | CUDA при доступности, иначе CPU | Задайте `cpu`, если видеопамять занята Ollama |
| `RAG_CONTEXT_MESSAGES` | `5` | Число сообщений в контексте, включая текущую реплику |
| `RAG_TOP_K` | `6` | Число найденных фрагментов для проверки (1–12). Меньшее значение сокращает запрос к модели, но может исключить альтернативный пункт. |
| `RAG_NUM_CTX` | `8192` | Контекст Ollama в токенах. Должен вмещать инструкции, диалог и найденные фрагменты. |
| `RAG_NUM_GPU` | выбор Ollama | Число слоёв генеративной модели на GPU. Можно уменьшить при нехватке видеопамяти. |
| `RAG_OLLAMA_TIMEOUT` | `240` | Таймаут чтения ответа Ollama в секундах |
| `RAG_EMBED_MODEL` | `bge-m3` | Эмбеддинги для документов и запросов |
| `RAG_DOCS_DIR` | `documents` | Папка с актуальными документами |
| `RAG_TESSDATA_DIR` | `.ocr-models` | Каталог с моделями rus.traineddata и eng.traineddata |
| `RAG_DATA_DIR` | `.rag` | Постоянные данные |
| `QDRANT_URL` | пусто | При заполнении используется сервер Qdrant |
| `QDRANT_COLLECTION` | `regulations_v1` | Выделенная коллекция этого приложения |
| `RAG_REVIEW_TOKEN` | пусто | Ключ специалиста. Без ключа доступен чат |

Для другого корпуса или модели эмбеддингов используйте новую папку данных и, при работе с сервером, отдельную коллекцию. Ключ, документы и папку с обращениями храните локально.
